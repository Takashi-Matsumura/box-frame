# 業務マニュアル作成ガイドライン

> **Simple is Best!**
> - 分かりやすく
> - 作りやすく
> - メンテしやすい

---

## 1. 文書構成

業務マニュアルは以下の3つの文書で構成する。

| 文書 | 内容 |
|------|------|
| 表紙＆改定履歴 | 更新履歴を記載 |
| 業務フロー図 | 業務全体の流れを記載（スイムレーンフローチャート） |
| 作業手順書 | 業務フロー内の1つの作業と1対1で作成 |

---

## 2. 業務フロー図作成手順

### 2.1 目的

業務フロー図は以下の目的で活用する：
- **引継ぎ者への説明**
- **標準化**
- **業務改善**
- **KPI定義**

業務フローは**スイムレーンフローチャート**で記述する（縦または横）。

### 2.2 スイムレーンフローチャートの部品

| 記号 | 名称 | 説明 |
|------|------|------|
| 楕円 | 状態 | 業務の開始条件、終了結果などの状態 |
| 長方形 | 作業 | 実際に工数・時間が発生する作業やシステム処理。※作業の粒度：「情報を受け取って、一気に作業を行い、中間成果物を出力する」まで |
| ひし形 | 分岐 | 判断などによる作業の流れの分岐。※作業の中での分岐は作業手順書の代替フローや例外フローで記載 |
| 矢印（実線） | 作業の流れ | 作業を行う順番 |
| 角丸長方形 | 伝達データ | 作業から作業へと受け渡されていくデータ |
| 円筒 | 蓄積データ | 作業の流れとは別に蓄積されているデータ |
| 矢印（点線） | データの流れ | 作業とデータの入力・出力の向き |

### 2.3 作成手順

#### 手順1: 範囲の定義

- 単位は**組織**
- 中心となる部門のひとまとまり作業で**開始のきっかけ**から**役割を果たし終える**まで

#### 手順2: 登場人物の洗出し

以下の3つの視点で登場人物（アクター）を特定する：
- **入力（供給者）**: 業務のトリガーとなる情報を提供する人・部門
- **出力（顧客）**: 業務の成果物を受け取る人・部門
- **パートナー**: 業務の途中で関わる人・部門

#### 手順3: 作業の記述

- 単位は**作業者**
- 作業の粒度：「**情報を受け取って、一気に作業を行い、中間成果物を出力するまで**」

#### 手順4: 入出力の記述（伝達データ、蓄積データ）

- 「作業」が使用するデータ
- 「作業」が生み出す「データ」

## 3. 業務フロー図の活用

### 3.1 活用1: 付加価値分析

業務フロー図上の各作業を以下の3つに分類し、業務改善に活用する。

#### VA（Value Added）: 価値を生むプロセス

VAと定義されたプロセスは、業務を含めたQCD（品質、コスト、納期）を基本として「顧客ニーズ」をより満たすための方策とそのプロセスの完遂が改善の基本方針。

#### NVA（Non Value Added）: 価値を生まないプロセス ≒ ムダ

顧客視点から見て"価値を生まないプロセス(NVA)"については**基本的には排除を検討**。
最大のポイントは「自社都合」の尺度を使ってはならない、ということ。

**NVAの例：**
- 過剰品質
- 定義されていない二重チェック、三重チェックなど
- 必要以上の「承認プロセス」
- 生産、サービスプロセスにおける各種調整プロセス
- 社内管理目的の複雑なシステム

#### BV（Business Value）: 付加価値は生んでいないが、タスク達成上不可欠なプロセス

価値は生んでいないが、タスク達成上、不可欠なプロセスは、NVAではなく、別に区分し効率化（≒排除）を基本方針とする。

但し、プロセス改善という視点から、プロセスをドラスティックに改善する必要がある場合には、BVという概念を加えると「原則的に排除」と判定されるプロセスが少なくなる傾向になる。
結果として、現状肯定型の改善になってしまう可能性が高い。

### 3.2 活用2: KPIの定義

業務フロー図上でKPIを定義することで、業務の測定ポイントを明確にする。

**KPIの例：**
- 受付工数
- 納期遵守率
- 納期回答リードタイム

## 4. 作業手順書作成方針

### 4.1 ユースケース記述書形式

作業手順書は**ユースケース記述書を流用**して作成する。

| 項目 | 説明 |
|------|------|
| **作業名*** | 業務フロー図の作業と対応する作業名を書く |
| 概要 | 作業の内容を要約したものを書く |
| 目的 | 作業を実行する目的を書く。「○○するため」という風に書く。こうすることで、作業全体を「○○するために、(A氏またはシステムが)△△を□□する」と読むことができる |
| アクター | 作業に関係するアクター（業務フロー図上で作業と関連線で結ばれたアクター）をリストアップして書く |
| 開始条件 | 作業を開始する条件を書く。開始のきっかけ・引き金（トリガー） |
| 事前条件 | 作業が開始する前に満たされているべき条件を書く |
| **イベントフロー - メイン*** | 作業に伴って起きる（イベントフロー）のうち、正常に処理が進んだ場合の手順を書く。主語をアクターまたはシステムと明示し、アクターのやることとシステムのやることを順序を表す番号をつけて書く |
| イベントフロー - 代替 | イベントフローの内、途中で問題が発生した場合などに分岐する、メインフローの代わりとして行う作業ステップを書く。※代替フローを実行しても事後条件は満たされる。※代替フローの中での代替は誤り |
| イベントフロー - 例外 | イベントフローのうち、作業の実施を断念しなければならないような場合の手順を書く。代替するフローがない例外のもの。※例外フローを実行した場合、事後条件は満たされない。※例外フローの中での例外フローは誤り |
| 事後条件 | 作業が実行された後に満たされているべき条件を書く |
| 備考 | 何を書いてもよい。例えば、上記の項目に収まらないような記述や、詳細な解説などを書く |

**\*は必須項目**

### 4.2 作業手順書の記述例

```
ユースケース名: 1. ユーザーを登録する
要約:         顧客情報を入力し、システムは入力された情報でユーザーを登録し、ユーザーIDを発番する
主要アクタ:   顧客
事前条件:     なし

基本フロー:
  1  顧客は、「新規登録」を実行する
  2  システムは、ユーザー情報入力画面を表示する
  3  顧客は、ユーザー登録に必要な情報を入力する
  4  システムは、入力されたユーザー情報を表示する
  5  顧客は、表示された情報を確認して「登録」を実行する
  6  システムは、ユーザーIDを発番する
  7  システムは、入力されたユーザー情報とユーザーIDをDBに登録する
  8  システムは、発番した「ユーザーID」を表示する

代替フロー:
  1. 顧客の入力に漏れがある
     1-1  システムは、「未入力」のメッセージを表示する
  2. 入力された情報で既にユーザーが登録済みの場合
     2-1  システムは、登録済みであるメッセージを表示する
     2-2  顧客は、基本フロー1からやり直す
```

## 6. 業務分掌機能との対応

このガイドラインは、BoxFrameの業務分掌機能と以下のように対応する：

| ガイドライン | 業務分掌機能 |
|-------------|-------------|
| 範囲の定義 | 業務概要・目的 |
| 登場人物の洗出し | ステークホルダー、アクター |
| 作業の記述 | 業務フロー |
| 入出力の記述 | インプット/アウトプット |
| 使用システム | 使用システム・ツール |
| KPIの定義 | KPI/成果指標 |
| 付加価値分析 | リスク・課題、改善提案 |
| 作業手順書 | （今後の拡張候補） |

### 今後の機能拡張候補

1. **付加価値分析（VA/NVA/BV）機能**
   - 各作業にVA/NVA/BVのタグ付け
   - ムダの可視化と改善提案

2. **作業手順書（ユースケース記述）機能**
   - 業務フロー図の各作業に対応する詳細手順書
   - メイン/代替/例外フローの記述

3. **スイムレーンフローチャートの自動生成**
   - 業務分掌のアクター・フローからフローチャートを生成
   - VA/NVA/BVの色分け表示
